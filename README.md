# Прогнозирование популярности музыкальных треков Spotify

Репозиторий содержит экспериментальную часть ВКР по задаче прогнозирования популярности музыкальных треков на основе мультимодальных признаков: метаданных Spotify, характеристик артиста, аудио-признаков и текстов песен.

## Цель работы

Цель проекта — исследовать, какие группы признаков сильнее всего влияют на качество предсказания популярности трека, и провести поэтапное ablation study.

Целевая переменная:

- `popularity` — показатель популярности трека в Spotify, принимает значения от 0 до 100.

Задача решалась как задача регрессии. Дополнительно рассчитывалась метрика AUC для оценки способности модели ранжировать треки по принципу «более популярный / менее популярный».

## Структура экспериментов

Эксперименты разбиты на несколько уровней.

### Level 1 — Spotify baseline

Базовый уровень использует только стандартные high-level audio features из Spotify:

- `danceability`
- `energy`
- `loudness`
- `speechiness`
- `acousticness`
- `instrumentalness`
- `liveness`
- `valence`
- `tempo`
- `duration_ms`
- `key`
- `mode`
- `time_signature`
- `explicit`

Этот уровень используется как основной baseline.

### Level 2 — контекстные признаки артиста и метаданные

На втором уровне добавляются признаки, связанные с артистом и контекстом трека.

В работе отдельно рассматриваются:

- **L2a Internal** — признаки, рассчитанные на основе самого датасета. Этот уровень содержит утечку данных и используется как leakage-aware upper bound, а не как честная модель для практического применения.
- **L2b External** — внешние признаки артистов, полученные из Last.fm.
- Комбинации Spotify-признаков и контекстных признаков.

Важно: высокие результаты конфигураций с `L2a Internal` интерпретируются как демонстрация эффекта утечки данных.

### Level 3 — аудио-признаки

На третьем уровне используются признаки, извлечённые из аудио-превью треков:

- **Librosa** — handcrafted audio features;
- **VGGish** — аудио-эмбеддинги;
- **CLAP** — contrastive audio embeddings;
- комбинации этих признаков со Spotify baseline.

Для Level 3 используется audio subset — подмножество треков, для которых удалось получить и обработать аудио. Поэтому Spotify baseline внутри Level 3 считается именно на этом же audio subset для честного сравнения.

### Level 4 — текстовые признаки

На четвёртом уровне используются тексты песен:

- lyrics, полученные через Genius;
- текстовые эмбеддинги;
- комбинации текстовых признаков со Spotify baseline.

Так как тексты доступны не для всех треков, эксперименты Level 4 проводятся на lyrics subset.

### Level 5 — финальная мультимодальная абляция

Пятый уровень объединяет несколько групп признаков и сравнивает:

- content-only конфигурации;
- конфигурации с контекстом артиста;
- полные мультимодальные конфигурации;
- варианты с PCA для снижения размерности;
- финальные модели и ансамбли.

Важная интерпретация:

- content-only модели показывают качество без использования внутренних leakage-признаков;
- FULL-конфигурации с internal context показывают верхнюю границу качества, но не должны интерпретироваться как полностью честная практическая оценка.

## Использованные модели

В экспериментах использовались следующие модели:

- Linear Regression
- Random Forest
- XGBoost
- LightGBM
- Ridge Regression для отдельных высокоразмерных embedding-конфигураций
- Stacking / tuned models в финальном сравнении

## Метрики

Для оценки использовались:

- **MAE** — средняя абсолютная ошибка;
- **RMSE** — корень из среднеквадратичной ошибки;
- **R²** — доля объяснённой дисперсии;
- **AUC** — качество ранжирования треков по бинарной постановке «популярный / непопулярный».

## Данные и промежуточные файлы

В репозитории сохранены как исходные/очищенные данные, так и промежуточные признаки:

- `dataset.csv` — исходный датасет;
- `dataset_clean.csv` — очищенный датасет после дедупликации;
- `audio_features.csv` — итоговые аудио-признаки, рассчитанные на основе Librosa, VGGish и CLAP;
- `text_features.csv` — текстовые признаки;
- `lastfm_cache.csv` — кэш внешних данных артистов из Last.fm;
- `genius_lyrics_cache.json` — кэш текстов песен;
- `level*_results.csv` — сохранённые итоговые метрики по каждому уровню.

Файлы `.pkl` в папке `models/` содержат обученные модели и preprocessing-объекты: scaler'ы, PCA-преобразователи и финальные модели.

## Как воспроизвести эксперименты

Общая логика запуска:

1. Запустить `Level1_v3.ipynb` для очистки данных и получения baseline.
2. Запустить `Level2_v3.ipynb` для экспериментов с контекстными признаками.
3. Запустить `Level3_v3.ipynb` для аудио-признаков.
4. Запустить `Level4_v3.ipynb` для текстовых признаков.
5. Запустить `Level5_v3.ipynb` для финального мультимодального сравнения.

При этом тяжёлые промежуточные файлы уже сохранены в репозитории, поэтому для проверки результатов не требуется заново скачивать аудио или тексты песен.

## Основные выводы

1. Базовые Spotify-признаки дают ограниченное качество, но являются важным baseline.
2. Внутренние contextual-признаки сильно повышают качество, однако содержат утечку данных и должны рассматриваться как upper bound.
3. Аудио-эмбеддинги VGGish и CLAP дают дополнительную информацию по сравнению с handcrafted Librosa-признаками.
4. Текстовые признаки также дают прирост качества, особенно в комбинации со Spotify-признаками.
5. Наиболее сильные результаты достигаются при объединении разных модальностей, однако результаты с internal context необходимо интерпретировать осторожно.

## Ограничения

- Внешние признаки артистов зависят от времени сбора данных.
- Тексты и аудио доступны не для всех треков, поэтому часть экспериментов проводится на подмножествах.
- L2a/Internal-признаки содержат data leakage и используются только для анализа верхней границы качества.
- Отдельные сохранённые модели в `models/` относятся к финальным конфигурациям; некоторые ablation-модели воспроизводятся через соответствующие ноутбуки и сохранённые таблицы результатов.
